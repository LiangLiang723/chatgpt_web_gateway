# Versioning（版本规范）

本项目使用 `主版本.次版本.修订版本` 三段式版本号，并采用以下双重表示：

- **对外展示、CHANGELOG、Git Tag（Git 版本标签）：** `V0.0.1`、`V1.0.2`
- **`package.json`：** `0.0.1`、`1.0.2`，不带前缀 `V`
- **根目录 `VERSION`：** 保存对外展示版本，例如 `V0.0.1`

`VERSION`、`package.json` 与 `CHANGELOG.md` 的当前版本必须保持一致。

## 升级规则

### 修订版本 PATCH（补丁版本）

用于兼容性 bug（缺陷）修复、小型文档修正或不改变公开能力的维护：

```text
V0.0.1 → V0.0.2
V1.0.0 → V1.0.1
```

### 次版本 MINOR（次版本）

用于向后兼容的新功能、新接口能力或明显功能增强：

```text
V0.0.2 → V0.1.0
V1.0.2 → V1.1.0
```

### 主版本 MAJOR（主版本）

用于稳定版本后的不兼容变更，或项目从早期开发阶段进入第一个正式稳定版本：

```text
V0.x.y → V1.0.0
V1.x.y → V2.0.0
```

## 版本阶段

- `V0.x.y`：早期开发阶段。允许架构和 API（应用程序接口）快速演进，但每次公开变更仍必须记录。
- `V1.0.0`：第一个可长期使用的稳定版本。
- `V1.x.y` 及以后：遵循向后兼容的版本升级原则，不兼容变化提升主版本号。

## 发布要求

发布一个新版本时必须同步：

1. 更新根目录 `VERSION`。
2. 更新 `package.json` 的 `version`。
3. 在 `CHANGELOG.md` 新增对应版本记录。
4. 如版本变化影响当前项目状态，更新 `docs/PROJECT_STATE.md`。
5. 运行 `pnpm check:version` 和 `pnpm verify:repo`。
6. Git Tag 使用带大写 `V` 的版本号，例如 `V0.0.1`。

README 只描述项目当前能力、定位和使用方式，不承担版本历史记录职责。
