# V0.1.4 Pi Browser Runtime Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make real Pi coding-agent requests with large project instructions and normal tool sets survive the ChatGPT Web Browser path, while exposing actionable safe diagnostics and container-safe proxy configuration.

**Architecture:** Preserve the current Conversation/Tool protocol and fix the size-sensitive Composer transport instead of truncating caller context. Add safe Page diagnostics to Driver failures, log mapped HTTP/SSE execution errors, make the explicit diagnostics endpoint run a bounded Page/auth probe, and pass optional generic proxy variables through the Docker Compose boundary.

**Tech Stack:** TypeScript 6, Fastify 5, Playwright 1.62, Vitest 4, Docker Compose, existing ChatGPT selector/auth/PagePool abstractions.

**Spec:** `docs/superpowers/specs/2026-08-31-v0.1.4-pi-browser-runtime-design.md`

## Global Constraints

- Do not silently drop or truncate caller tools, system instructions, developer instructions, or history.
- Public OpenAI-compatible error codes/messages remain stable; Playwright internals are server-log diagnostics only.
- Diagnostics must not expose prompt/tool contents, cookies, API keys, Profile paths, proxy credentials, or attachment bytes.
- Real ChatGPT validation uses `CHATGPT_PROXY_SERVER=http://192.168.3.83:7890` and is run only after deterministic implementation is complete.
- No Docker registry image, GitHub Release, or Git tag is published unless explicitly requested.
